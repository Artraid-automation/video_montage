## Канонический процесс

### Фаза 1 — подготовка решения

Вход: пронумерованные raw-сегменты; отдельный WAV и screen/camera feeds; настройки бренда; библиотека B-roll.

Автоматическая работа:

- инвентаризация и техническая проверка медиа;
- транскрибация каждого сегмента;
- распознавание дублей, фальстартов, пауз и лишних фрагментов;
- предложение точных текстовых cuts;
- поиск повторно используемого B-roll и briefs для новых motion scenes;
- waveform-sync внешнего звука;
- создание образцов color grade;
- общий обзор и файлы по каждому сегменту.

Человеческий выход: `review.md`, `segments/NN/transcript.md`, планы B-roll/motion, grade samples и sync report, плюс `film-continuity.json` (сегменты как части одного ролика). Фаза 1 не имеет права создавать видимость готового ролика: ее результат — проверяемое монтажное решение.

### Gate 1 — редакторское утверждение

Человек проверяет cuts в контексте текста, возвращает ошибочно удаленные реплики, принимает/заменяет B-roll и motion concepts, выбирает grade, подтверждает sync и явно разрешает фазу 2. Без approval first pass не рендерится. Approve запрещён при `film-continuity.verdict == BLOCKED` (KEEP-дубль между сегментами).

### Фаза 2 — сборка и самопроверка сегментов

- применить только утвержденные cuts;
- синхронизировать звук, наложить grade, PiP, B-roll и графику;
- генерировать motion-assets через очередь;
- рендерить каждый сегмент отдельно;
- заново транскрибировать каждый rendered segment;
- сравнивать expected kept transcript с фактическим;
- проверять визуальные кадры и технические параметры;
- enforce `visual_render_policy` from `render-contract.json` (overlay motion, caption size, no producer notes on cards);
- автоматически повторять сегмент при детектируемой ошибке.

Человеческий выход: review MP4, постмонтажный `rendered-transcript.md`, `verification.md` и общий Gate 2 review.

### Gate 2 — просмотр каждого результата

Человек смотрит каждый сегмент полностью, читает постмонтажный транскрипт и пишет локальные `[fix]`-замечания. Скриншот считается полноценным входом для визуальной ошибки. Повторяющаяся ошибка должна дать два результата: исправленный сегмент и новое автоматическое правило проверки.

### Фаза 3 — финализация и безопасная уборка

- применить fixes и повторить проверки;
- объединить финальные сегменты и экспортировать master;
- выполнить технический QC;
- сформировать название, описание и точные chapters;
- поместить master и publishing package в архив;
- проверить существование, размер и checksum архивной копии;
- добавить новые reusable assets в библиотеку;
- только после проверки архива разрешить очистку тяжелого workdir.

Публикация на YouTube остается ручной.

## Наша локальная адаптация

| В референсе | В продукте v1 |
|---|---|
| Tubery API | `library/broll/` с metadata, proxies и поиском. |
| Spark Drop | Локальный publishing package: title, description, chapters, manifest. |
| Dropbox | Настраиваемая archive root с checksum-проверкой. |
| ElevenLabs | Provider interface: ElevenLabs при наличии ключа, Whisper fallback. Повторная транскрибация обязательна. |
| Hyperframes | Motion provider interface; scene contract и visual QC обязательны. |
| Claude Code skills | Один продуктовый оркестратор и узкие адаптеры. |
| Timeline editor | Не нужен для gates; Resolve — необязательный finishing adapter. |

## Граница достоверности

Ролик показывает поведение и UX, но не публикует исходный код, prompts или schemas. Мы повторяем проверяемую архитектуру процесса, а не заявляем совместимость с закрытой реализацией автора.
