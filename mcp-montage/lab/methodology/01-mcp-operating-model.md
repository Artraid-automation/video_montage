# MCP operating model

## Стек

```
Наблюдатель
    ↓ задача / вкус
Агент (Cursor)
    ↓ MCP tools
resolve_mcp_bridge.py
    ↓ HTTP :9876
CursorBridge.py (внутри Resolve)
    ↓ Scripting API
DaVinci Resolve Free 21
```

## Перед любой сессией

1. Resolve открыт, нужный проект загружен
2. Запущен `CursorBridge`
3. `get_resolve_status` → `connected: true`
4. Прочитан `source-map/current.md` и актуальный `runs/`

## Режимы работы агента

| Режим | Когда | Что можно |
|-------|--------|-----------|
| `research` | разбор референса, методика | только `lab/`, без правок Resolve |
| `plan` | план таймлайна | markdown в `runs/`, без Resolve |
| `build` | сборка | MCP write после плана |
| `fix` | точечная правка | узкий scope, запись в experiments |
| `export` | рендер | настройки + очередь, путь в `06_exports` |

По умолчанию новый чат начинается в `research`/`plan`, пока наблюдатель не сказал собирать.

## Контракт атомарной инструкции

Каждый файл в `atoms/`:

- **Цель** — одна фраза
- **Вход** — что нужно (клип, таймкод, файл)
- **Шаги MCP** — tool names + параметры
- **Ручной fallback** — если API/Free не умеет
- **Проверка** — как понять, что ок
- **Известные фейлы** — ссылки на `experiments/`

Шаблон: `atoms/_template.md`.

## Контракт прогона (`runs/`)

1. Цель прогона
2. Референс / пресет
3. Исходники
4. План
5. Что сделано фактически
6. Что сломалось
7. Что вынести в atoms/presets

## Граница ответственности

Агент сам решает: пути, порядок атомов, какие MCP tools, имена пресетов, структуру lab.
Наблюдатель решает: «нравится / не нравится», смысл текста, стоп на деструктиве, финальный ship.
