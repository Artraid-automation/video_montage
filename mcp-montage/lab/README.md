# lab — база знаний MCP-монтажа

Рабочая память проекта. Сюда пишем всё, что после 20 прогонов должно позволять команду уровня «сделай крутое видео».

## Решение по расположению

`lab/` в корне проекта (ASCII-имя). Исходники рилса остаются в `рилс/...`.
Почему так: скрипты/MCP/логи стабильнее на коротких ASCII-путях; медиа и knowledge base не смешиваются.

## Карта папок

| Папка | Зачем |
|-------|--------|
| `methodology/` | принципы, роли, правила MCP-монтажа |
| `atoms/` | атомарные действия: как повернуть, как субтитры, как переход |
| `pipelines/` | сборки атомов в сценарии (рилс v1, субтитры, экспорт…) |
| `presets/` | стили, субтитры, Resolve-пресеты (после реверс-инжиниринга) |
| `references/` | разбор референсов (шрифт, цвет, ритм, эффекты) |
| `runs/` | журнал каждого прогона |
| `experiments/` | удачные/неудачные попытки по темам |
| `source-map/` | где лежат исходники текущего рилса |
| `checklists/` | чеклисты перед/после сборки |

## Правило записи

Любое действие агента в Resolve = цикл:

1. **Распознать** задачу
2. **Сделать** (или объяснить блокер)
3. **Записать** в `atoms/` или `experiments/`
4. Если повторилось 2+ раза → поднять в `pipelines/` или `presets/`

## Роли

- **Агент** — техрешения, пайплайн, 80% рутины, документация
- **Наблюдатель** — вкус, стоп/продолжай, финальный ok по кадру/смыслу
- Технические A/B агент не спрашивает, кроме креативных развилок
