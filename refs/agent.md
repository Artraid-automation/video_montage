# agent.md — измерительный контур референсов
Актуально на 25.08.2026.

## Что здесь
```
src/          скачанные референсы (в git не идут: чужой контент + вес)
.venv/        opencv 4.x + yt-dlp (в git не идут)
analysis/     probe2.py  — лицо, субтитры, цвет            (шаг 0.20 с)
              probe3.py  — движение кадра, смены картинки и текста (шаг 0.05 с)
              rhythm.py, motion.py, composition.py — сводки в консоль
              profile.py — сводит всё в ../style/measured-v1.json
              ref*-probe*.json — сырые временные ряды (в git идут: это доказательства)
```

## Неочевидное
- **opencv 5.x не подходит:** в нём нет `cv2.CascadeClassifier`. Нужен `>=4.8,<5`,
  как и в `mcp-montage/requirements-framing.txt`.
- **Системный yt-dlp (2024) Instagram уже не берёт** — отдаёт «login required».
  Свежий из venv берёт без куки. Обновлять venv, а не спорить с системным.
- **Кадры читаются последовательно через `grab()`**, а не `cap.set(POS_FRAMES)`:
  seek по кадру на 60 fps превращает разбор в часы.
- **Зум считается по периферии кадра, не по лицу.** Рамка Haar дрожит на 2–3% между
  соседними кадрами — по ней «плавное движение» находится в 70% проб, которых нет.
  Первая версия анализа именно так и ошиблась.
- **Композиция считается только по кадрам без верхней вставки** (`face.cy_pct < 55`):
  в референсах говорящая голова часто занимает нижнюю половину, и общая медиана линии
  глаз уезжает на 65% высоты — это артефакт формата, а не приём.
- Детектор верхней вставки в `probe2.py` завышает (даёт 70–85%) и на выводы не влияет —
  вставки мы всё равно не делаем. Чинить его смысла нет, пока формат не понадобится.
- Порог склейки берётся от собственного шума ролика (97-й перцентиль разницы кадров),
  а не константой: у роликов разный уровень движения в кадре.

## Как повторить на новом референсе
```
.venv/bin/yt-dlp -o "src/refN.%(ext)s" "<url>"
.venv/bin/python analysis/probe2.py src/refN.mp4 analysis/refN-probe2.json
.venv/bin/python analysis/probe3.py src/refN.mp4 analysis/refN-probe3.json
.venv/bin/python analysis/profile.py     # перепишет ../style/measured-v1.json
```
Добавляя ролик — вписать его номер в `REFS` в `profile.py` и в шапку `source` там же.

## Опознание гарнитуры (`font_match2.py`)
- **Сопоставлять маску с текстом из ASR нельзя:** субтитр в кадре не всегда совпадает со словом,
  которое распознал whisper. Первая версия дала совпадение 0.22–0.42 при ошибке ширины 50–75% —
  это признак того, что сравниваются разные слова, а не разные шрифты. Правильный путь:
  вырезать маски (`grab_caption_samples.py`), прочитать слова глазами, вписать их в `SAMPLES`.
- Кандидаты качаются **из `github.com/google/fonts`, а не с `fonts.google.com/download`**:
  второй отдаёт HTML-страницу под видом zip (все файлы выходят ровно ~193 КБ — верный признак).
- Переменные шрифты ставятся в вес через `font.set_variation_by_axes([wght])`; статические
  начертания этот вызов игнорируют, поэтому перебор идёт по 900/800/700 с отбором лучшего.

## ASR: чем и зачем
- Для **измерения пауз** хватает whisper small: важны границы слов, а не буквы. Проверено —
  large-v3 на ref4 дал p90 пауз 0.040 против 0.080 и речь 97% против 94%, вывод не изменился.
- Для **боевых субтитров** small не годится: текст идёт на экран. GigaAM на `stt-host` сильнее
  на русском, но его обвязка (`~/gigaam/gigaam_server.py`) режет речь по silero VAD и
  **пословных таймингов не отдаёт** — нужен отдельный шаг выравнивания.
- Для **реза пауз** ASR вообще не нужен: silero VAD на `stt-host` детектит границы речи напрямую
  и не зависит от того, верно ли распознано слово.
